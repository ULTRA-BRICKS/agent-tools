# ChatGPT Guardian implementation brief — Refs #891

The authoritative user requirements are safe recovery of the latest active ChatGPT UI `Thinking failed` status only, exact `го`, 20 seconds stable evidence, at least 60 seconds per chat and at most three attempts/hour, durable crash dedup, running/draft/challenge/ambiguous/manual safety stops, account-wide observed Astra quota, explicit per-chat verified Sol Extra High consent, independent home/glide.vc profiles, observe default, reusable local package/lifecycle/service/CLI, HA PR #10 adapter and pm-cli integration notes. Prior source bundle is unavailable. No CAPTCHA bypass or token/cookie extraction is permitted. Push isolated feature branch and open PR; do not merge.

Implementation: pure evidence policy and durable SQLite controls/reservations; explicit fail-closed DOM contract with synchronous final checks; marked profile lifecycle with one owner and manual login mode; authenticated loopback control service and lazy optional browser/HA imports; HA adapter sharing lifecycle/API lock and preserving challenged/restored tabs; integration notes grounded in external PR commit `186ffce89a1cb0dcb396e13a5897d8af938164e0`.

Verification plan: red/green stable-failure policy first; adversarial policy/rate/crash/control tests; actual Chrome structural fixtures with intercepted HTML; independent safety review; lint/typecheck; build/install wheel and CLI entrypoint; staged multi-model review; isolated branch push and Forgejo PR/remote verification. Live activation remains conditional on human login and account UI calibration. Legacy external deployment and pm-cli repositories are not changed here.

Account-state contract: `home` and `glide.vc` identify separate accounts, with independent default SQLite files and control tokens. Global CLI `--workspace` selects the same account for run/status/watch/consent/stop; default home, compatible run-local alias, conflicting values refused. Explicit `--state`/`CHATGPT_GUARDIAN_STATE` sharing is permitted only within the database's persisted workspace/account identity. Existing unscoped files and legacy default files refuse startup pending offline reconciliation of stops, consent, budgets and uncertain intents; no silent migration or discarded history. HA defaults to `/data/guardian-state/<workspace>/state.sqlite`. Account labels are operator assertions, not credential-derived identity verification.

HA API preparation and dispatch use calibrated contract selectors and synchronous DOM checks, preserving an intervening human draft and enforcing exact per-chat Sol consent. Reply polling uses the calibrated running selector; challenge/sign-in while awaiting a reply persists a human stop. Legacy bridge composer/send selectors cannot authorize mutations.
