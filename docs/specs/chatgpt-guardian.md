The authoritative user requirements are safe recovery of the latest active ChatGPT UI `Thinking failed` status only, exact `го`, 20 seconds stable evidence, at least 60 seconds per chat and at most three attempts/hour, durable crash dedup, running/draft/challenge/ambiguous/manual safety stops, account-wide observed Astra quota, explicit per-chat verified Sol Extra High consent, independent home/glide.vc profiles, observe default, reusable local package/lifecycle/service/CLI, HA PR #10 adapter and pm-cli integration notes. Prior source bundle is unavailable. No CAPTCHA bypass or token/cookie extraction is permitted. Push isolated feature branch and open PR; do not merge.

Implementation: pure evidence policy and durable SQLite controls/reservations; explicit fail-closed DOM contract with synchronous final checks; marked profile lifecycle with one owner and manual login mode; authenticated loopback control service and lazy optional browser/HA imports; HA adapter sharing lifecycle/API lock and preserving challenged/restored tabs; integration notes grounded in external PR commit `186ffce89a1cb0dcb396e13a5897d8af938164e0`.

Verification plan: red/green stable-failure policy first; adversarial policy/rate/crash/control tests; actual Chrome structural fixtures with intercepted HTML; independent safety review; lint/typecheck; build/install wheel and CLI entrypoint; staged multi-model review; isolated branch push and Forgejo PR/remote verification. Live activation remains conditional on human login and account UI calibration. Legacy external deployment and pm-cli repositories are not changed here.

Account-state contract: `home` and `glide.vc` identify separate accounts, with independent default SQLite files and control tokens. Global CLI `--workspace` selects the same account for run/status/watch/consent/stop; default home, compatible run-local alias, conflicting values refused. Explicit `--state`/`CHATGPT_GUARDIAN_STATE` sharing is permitted only within the database's persisted workspace/account identity. Existing unscoped files and legacy default files refuse startup pending offline reconciliation of stops, consent, budgets and uncertain intents; no silent migration or discarded history. HA defaults to `/data/guardian-state/<workspace>/state.sqlite`. Account labels are operator assertions, not credential-derived identity verification.

HA API preparation and dispatch use calibrated contract selectors and synchronous DOM checks, preserving an intervening human draft and enforcing exact per-chat Sol consent. Reply polling uses the calibrated running selector; challenge/sign-in while awaiting a reply persists a human stop. Legacy bridge composer/send selectors cannot authorize mutations.

## Resource policy: passive evidence vs mutation admission (Refs #1020, 0.3.8)

Two separate questions, never conflated: _what can be read_ and _may anything be changed_.

**Classification (one normalisation, `urls.conversation_identity`).** A page is a conversation tab when its URL, with query and fragment dropped and one trailing slash allowed, is `https://chatgpt.com/c/<id>` or the project form `https://chatgpt.com/g/g-p-<32 hex>[-<slug>]/c/<uuid>`; all such variants share the identity `https://chatgpt.com/c/<id>`. Every other open page is auxiliary: `/space?tab=all`, `about:blank`/new tab, other chatgpt.com pages, a project URL whose id is not a UUID, and any external site (e.g. `https://example.com`) — none is ignored. A duplicate tab of one conversation URL counts physically as a second conversation tab and keeps vetoing mutation for that chat (`enrolled_pages(...) == [page]`).

**Mutation admission (`live.resource_pause`, used by sends, Sol selection and `startup.restore`).** Mutation is paused when conversation tabs exceed the conversation budget (6, hard ceiling: `--max-pages` may only lower it; never raised, never disabled), when auxiliary tabs exceed the auxiliary budget (2, `AUXILIARY_PAGE_BUDGET`), or when host `MemAvailable` is below the floor (default 2048 MiB) or unreadable. Reasons, checked in this order: `conversation-budget`, `auxiliary-budget`, `memory-unavailable`, `low-memory`. Six conversations plus one `/space` tab is within budget. All earlier send vetoes are unchanged and independent of the budgets: running turn, draft, wrong identity, platform approval/permission UI (never accepted or denied), HTTP 401/403/429, quota, uncertain send; no retry or auto-clear.

**Passive evidence (observer, coverage, monitor health).** Read-only and bounded: no new tab, navigation, click, activation, close or permission UI; one 5 s read per already-open conversation; non-conversation pages are never read, and a duplicate tab of an already-read conversation is not read again. The passive cap is `PASSIVE_CONVERSATION_CAP` = 6 distinct conversations per cycle (enrolled chats first, then tab order). It deliberately equals the conversation budget: each read wakes a renderer, so reads stay inside the memory envelope the system is sized for instead of scaling with tab count. A mutation pause (budget or memory) never blanks evidence: the observer keeps reporting the real state of every conversation it reads and labels the snapshot `resource_paused` (`""` when not paused, null when the browser is unreachable) with `page_count`, `conversation_page_count`, `auxiliary_page_count` (counted from the same page list that was sampled), `max_pages`, `max_auxiliary_pages`, `min_available_mib`, `passive_cap`. Low memory is not a reason to stop reading already-open tabs (one bounded evaluate each; no tab is created or woken by navigation). A conversation beyond the cap is an `unobserved` session (`beyond-passive-cap`, status `unknown`), never a guessed state.

**Completeness.** `summary.observation_counts` counts enrolled chats by `current`, `stale` (page seen, evidence too old), `missing` (no page), `duplicate`, `error`, `unobserved`, `unavailable`; `summary.unobserved` counts every conversation (enrolled or not) the observer left unread. A conversation left unread is `unobserved` even when it also has a duplicate tab. `summary.coverage_complete` is true only when the browser is connected, the snapshot is fresh, every enrolled chat is `current` and no open conversation was left unread; it is independent of `resource_paused`. The coverage report carries `browser.conversation_pages`/`auxiliary_pages`, `summary.observation_complete` and `summary.resource_paused`.

**Limits in effect.** Sends use the `live` service's `--max-pages` and `--min-available-mib`. `live-sol` and `startup.restore` (also run by the coverage command) always apply the default limits (6 conversation tabs, 2 auxiliary tabs, 2048 MiB); restore counts the new conversation tab before it exists and also every chat it created in the same run that does not show as a conversation tab yet (still blank or loading). Such a pending tab may meanwhile also count as auxiliary; nothing is discounted, so the over-count fails closed. The observer labels `resource_paused` with its own `--max-pages`/`--min-available-mib` (defaults identical to `live`); run it with the same flags as the live service so the label matches the sender's real admission decision. The label never limits reads. In the coverage report `summary.resource_paused` and `summary.observation_complete` need a fresh snapshot and a browser verified in that run: `resource_paused` is `""` (admitted), a reason (paused), or null (unknown: stale snapshot or browser not verified).
