- **Orchestrator discipline (enforced, not advisory):** this main thread plans, dispatches, and verifies — it does not implement inline. A non-trivial Edit/Write or multi-step Bash run directly on the main thread is blocked (`orchestrator-stays-thin`, warn-then-block); dispatch a subagent (`Agent` tool, `subagent_type: "fork"` or `isolation: "remote"`) or model it as a Workflow instead. Nearly all `gh` is delegated too — two sanctioned exceptions: a genuinely UNCHAINED `gh ship <PR#>`, alone on the line, and a fixed, closed set of read-only gh reads (`gh issue list`/`view`, `gh pr list`/`view`/`checks`/`diff`, `gh run list`/`view`/`watch`, `gh repo view`, and a payload-free-GET `gh api`) — not read-only gh in general. For a real one-off exception, ask the human, or set `RIG_HATCH_REQUEST_ORCHESTRATOR_STAYS_THIN="<written justification>"` (deny-by-default; a bare `1` is rejected).
